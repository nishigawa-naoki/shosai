# 動作確認スクリプト（e2e）

ブラウザを自動操作して動作を確かめるスクリプト。`node e2e/<名前>.cjs` で実行する
（Claude Code では `sync.cjs` と `smoke.cjs` の実行だけを確認なしで許可している：`.claude/settings.json`。
スクリプトを増やしたら、そこにも追加する）。

ブラウザは手元の Edge / Chrome を自動で探す。見つからない場合は `BROWSER_PATH` で指定。

## sync.cjs — 2台の端末での同期・衝突

前提（どちらも起動したままにしておく）:

1. Firebase エミュレーター（auth と firestore）。ルールは本番と同じ `firestore.local.rules`（`npm run rules` で作る）をそのまま使う
   （スクリプトがルールから所有者のアドレスを読み取ってログインする。ルールは書き換えないこと）
   ```sh
   firebase emulators:start --only auth,firestore --project demo-novel   # ポートは firebase.json の emulators
   ```
   firebase-tools v15 以降は Java 21 以上が必要。古い Java なら `npx firebase-tools@14 emulators:start ...`
2. エミュレーターにつないだ開発サーバー（ポート 5199）。README の「エミュレーターで動かす」の環境変数で
   ```sh
   npx vite --port 5199 --strictPort
   ```

```sh
node e2e/sync.cjs
```

確認していること：初回保存、他端末への反映、古い画面・オフライン中の書き込みによる上書きの防止と解決、
カーソル位置の保持、保存失敗時に入力が残ること、メモ種類変更・並べ替え、削除後の後片付け、所有者以外のアカウント。

## autocorrect.cjs — 自動修正・ダイアログ・設定画面

前提は sync.cjs と同じ。作品作成・名前変更のダイアログ、自動修正の各項目（既定は無効）、
Ctrl+Z で修正だけ取り消せること、Markdown モードでは直さないこと、すぐ閉じた編集の自動保存し直しを確認する。

## migration.cjs — 旧形式データの移行

前提は sync.cjs と同じ。本文を一覧用の文書に持っていた旧形式のデータをエミュレーターに直接作り、
作品を開いたとき・話を直接開いたときに本文の文書へ移ること、一覧の文字数・書き出しを確認する。

## recovery.cjs — 保存の失敗からの回復

前提は sync.cjs と同じ。衝突を「この画面の版で保存」で解決したとき一覧のタイトルも書き直されること、
編集中に他の端末で削除されたとき保存できなかった入力を控えられること、Markdown のスキーム省略の外部リンクが
別タブで開くことを確認する。

## chapters.cjs — 章立て

前提は sync.cjs と同じ。章の見出しの追加・名前の変更・削除（話は残る）、章の末尾への話の追加、
見出しの並べ替えで章の区切りが変わること、章ごとの集計、書き出しに章の名前が入ることを確認する。

## share.cjs — 作品の共有（編集可・閲覧のみ）

前提は sync.cjs と同じ。共有相手のアカウントが要るので、実行中だけエミュレーターにテスト用アドレスを足したルールを
読み込ませ、終わったら `firestore.local.rules` の内容に戻す（ファイルは書き換えない）。
共有の追加・権限ごとの画面（編集可は書ける、閲覧のみは読むだけ）、ルールでの拒否（作品名・共有設定の変更、
閲覧のみの書き込み、共有されていない人の読み取り）、共有の解除を確認する。

## screenshots.cjs — README 用のスクリーンショット

前提は sync.cjs と同じ。デモ用のアカウント（`author@example.com`・`friend@example.com`）とデモデータをエミュレーターに入れ、
`docs/screenshots/` に画面を保存する。デモ用のアカウントでログインできるよう、実行中だけエミュレーターの許可リストに足し、
終わったら元のルールに戻す（ルールのファイルは書き換えない）。

## smoke.cjs — 公開サイトの簡易確認

`node e2e/smoke.cjs [URL]`。ログイン画面が出ること、設定・manifest・Service Worker を確認する（データは触らない）。
